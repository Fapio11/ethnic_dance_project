# 验收与证据边界

按实际范围选择检查，不为了完整性扩展设备或功能。PC-only 任务检查必要尺寸变化即可，不变成完整移动端改造。

| 门槛 | 需要的真实证据 | 不足以证明 |
| --- | --- | --- |
| 范围 | 修改文件与授权范围、原有流程核对 | 只说架构未变 |
| 艺术方向 | 实际视口对比保留项，材质/字体/构图/章节节奏 | 风格形容词、概念图 |
| 交互 | 实际点击/拖动/滚动，关键状态、反向、取消、重复输入 | 单张静态截图 |
| 可用性 | 可读性、键盘/焦点、反馈、加载/失败、布局溢出 | 仅代码审查 |
| 动画工程 | 控制者明确、资源/监听/时间轴清理、降级 | build 成功 |
| 业务回归 | 本次受影响导航、接口、数据流和功能检查 | 首屏正常 |
| 素材连续性 | 主体身份、实际相邻帧/片段、输入反向和重入 | 远距离抽帧 |

需要质量协助时，读取实际 Impeccable 的 `reference/critique.md`、`audit.md`、`polish.md`、`harden.md`、`adapt.md` 或 `optimize.md` 中与任务匹配的一个参考。审查只报告；修复必须已有相应实现授权。不要把命令列在报告里就视为已使用。

采用一次集中检查，按证据批量修复，再一次确认复查。新的实质失败可以触发后续工作，但不能无新证据重复微调。严重问题未解决就保持失败/阻塞状态。单次网页观察不宣称真机、生产发布或全平台通过。

## 浏览器和生成能力不足

宿主提供可用浏览器/截图能力时使用真实工具，不虚构浏览器 MCP。无法渲染时使用已有回归图像或局部静态证据，并说明目标、鲜度和限制；浏览器部分标记 `not-run`。接口或设备不可用只影响相应验收，不假装通过。

Oil Motion 的 Pilot 和生产门槛继续使用其真实版本 `references/qa.md`；已有媒体本地路线无需生成 Key。缺少生成权限/密钥仍可完成分镜、规格和代码可做部分。没有素材不能声称实际动画验收完成。

## 状态与交付

`planned` 是计划；`read` 是实际文件读取；`executed` 有真实工具输出；`verified` 还须指向验证证据；`skipped` 有适用性理由；`blocked` 指向权限或外部依赖；`not-run` 说明未执行原因。这些是本 Skill 状态约定，不是宿主的自动审核系统。

交付前形成一份简短执行账本：操作名、实际命令/工具、返回状态、证据位置。逐项对照最终回复；找不到本次工具返回的操作不得写为已执行或通过。读取检查指南不等于运行检查；`context` 的输出不等于 `detect` 的结果；空数组只有来自实际执行的对应工具才可解释为该工具结果。检查没运行就写 `not-run`，不要凭记忆、预期或另一代理的无证据报告补齐。即使 detector 实际返回空数组，也不能据此宣称交互或浏览器质量通过。

最终交付解释完成的范围、关键改变、测试结果、证据位置、剩余限制与下一步。创意选择、已实现代码、浏览器证据、设备/发布验收分别描述，不合并成一个完成状态。

## Skill 开发验证分层

创建本包时的静态检查、mock/脚本测试、离线路由演练、独立代理文件读取演练、Codex 发现/原生激活、真实浏览器验收应分别记录。`skills/list` 只证明发现；离线 planner 只证明结构化分流；这些都不能证明网站艺术质量。没有真实原生激活或另一操作系统时标记 `not-run`。
